# Controlled cohort expansion

Expansion is rejected unless execution is paused. Validate new institution-campus membership, refresh readiness, pass a migration dry run, require zero drift and record updated limits in a new Stage 7A configuration version. The proposal maker and checker must differ.

An accepted expansion appends an immutable decision and a new `PLANNED` execution version pinned to the new configuration. Checker approval is cleared, so go/no-go and maker-checker approval repeat. A running execution never expands directly; partial database changes roll back.
