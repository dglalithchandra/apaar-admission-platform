# Institution pilot onboarding

1. Confirm the synthetic institution and every campus belong to the intended tenant.
2. Record one of `READY`, `BLOCKED`, `DEGRADED` or `PAUSED`; do not expose blocked membership.
3. Verify approval-data freshness, API/template compatibility and role assignments.
4. Run migration dry run, reject invalid corrections explicitly and reach zero reconciliation drift.
5. Complete operator training, keyboard/accessibility tasks and support escalation.
6. Verify institution evidence can be read only through its tenant-scoped route.

The reference journey contains a ready institution, approval-freshness blocker, degraded identity dependency and paused institution across multiple campuses. All values are `SYNTH-` data.
